# 修复全仓审计发现的二十项问题

## 要改变什么

修复本会话全仓审计报告的编号 1–20，覆盖 `subagent`、`background-terminal`、`ask-user`、`goal`、`auto-compact`、`context-prune` 和 `bash-timeout`。每项都要有行为修复和能挡住旧实现的回归检查，不能只改文档或测试描述。

用户原话（2026-11-12）：「然后走 bi 流程，把那 20 个全部优化」。

## 已定方案与必须守住

- 台账严格对应报告 1–20，不把一项改名后漏掉，也不把审计中未列入报告的八项低影响问题混入本次范围。
- 先修项目信任、工具授权和本地文件边界，再修崩溃恢复、通知、交互与容量。
- 保留现有工具名、会话 ID、journal 的恢复作用、显式 `resume`、无寿命上限后台任务和七个扩展的 git 包加载方式。
- 不新增运行时依赖，不引入新的服务或通用框架。校验、进程清理、通知和容量限制放进现有所有者。
- 项目不信任时，项目角色正文、模型和工具配置不能影响执行；项目提供的角色名也不能向父工具提示注入换行或控制字符。
- 显式空工具列表表示无工具。自定义 child cwd 必须进入恢复调用。
- 崩溃恢复只能操作能验证属于本扩展的任务。清理路径不能信任 journal 中的任意路径，临时目录必须检查所有者、类型和权限。
- 完成通知不能因为 reload、元数据清理失败或历史淘汰而丢失。运行中与尚未通知的记录不能因容量限制被删除。
- `context-prune` 只恢复成功执行的 `ctx_reduce`；`bash-timeout` 和 `context-prune` 修改工具结果时保留 `structuredContent`。
- Escape 暂停 active goal，也不触发 auto-compact。400k 规则仍是 idle-only；本次按报告修正文案，不在没有安全边界设计时把压缩塞进 goal continuation。
- `ask_user` 顺序执行，AbortSignal 到达 RPC select/input；不新增用户此前明确删除的批次复核页。
- 用户原话（2026-11-12）：「把这个配置去掉，我们是不锁版本的」。保留 `.github/workflows/ci.yml` 删除 `node-version: 22` 的修改，不恢复版本锁。
- 行为变化同步对应 README。完成前跑全部 workspace 类型检查、全部测试、清单检查和七扩展联合加载。
- 实现与验证完成即可；不自动关闭 Issue 或 Epic，不自动 commit、push。

## 质量承诺

- **信息安全性**：不受信任的项目和本地其他用户不能越权修改子代理权限、注入父提示、读取任务数据或让清理逻辑操作任一路径；用公共入口和恶意文件 fixture 验证。
- **可靠性**：取消、reload、进程崩溃、输出写入失败和外部上报失败都有明确且可恢复的结果；用真实事件顺序、进程与失败注入测试验证。
- **性能效率**：完成记录和单批完成通知有确定上限，运行中与未通知工作不受淘汰；用突发完成与长历史测试验证。
- **可维护性**：每个编号至少有一条会在旧行为上失败的回归检查，检查穿过调用方实际使用的接口；最终全量检查防止跨扩展回归。
