# 堵住项目信任、工具授权与本地 journal 边界

## 目标与范围

完成台账 01–05：执行时沿用预检的 `projectTrusted`；过滤可注入提示的角色名；让 background 与 subagent 的临时目录和 journal 只能操作本用户、本扩展的任务；显式 `tools: []` 启动无工具 child。

只改 `subagent`、`background-terminal` 及各自测试和 README。保持现有角色发现、跨崩溃回收、工具名和 journal 恢复方式，不新增服务或运行时依赖。

## 风险与穿刺

最高风险是信任预检与真实执行走不同解析路径，以及恶意 journal 在扩展加载时触发进程和文件副作用。先用公共 execute 证明不受信任项目的 reviewer 正文、模型和工具不会进入 child argv；再用隔离临时目录证明 malformed journal 不会杀错 PID 或删除任一路径。两条打通后补齐空工具与目录权限检查。

## 方案

- `runSubagent` 的第二次角色解析显式接收预检使用的 trust 值。
- 角色名在发现和解析共用保守格式，拒绝控制字符和过长名称。
- 两个扩展在读写临时状态前检查目录所有者、非符号链接与私有权限；journal 只接受合法 ID、PID 和必需字段。
- 清理路径由验证过的 journal ID 推导，不采用 JSON 中的任意路径。
- 工具解析区分 `undefined` 与 `[]`；显式空列表映射到 Pi 的 `--no-tools`，不自动添加 codemode。

## 质量承诺

- **信息安全性**：不受信任项目不能提升 child 权限或注入父提示；恶意本地文件不能读取任务数据、杀错进程或删除任一路径。通过公共工具入口、argv 和隔离目录 fixture 验证。
- **可靠性**：合法 live/dead-owner journal 的原有回收行为保持，非法记录安全跳过并可诊断；运行现有 reaper 与进程测试。

## 验证

新增检查先在当前实现上复现失败，再修到通过。运行 `npm test --workspace subagent`、`npm test --workspace background-terminal`、两个 workspace 的 typecheck，以及真实进程组的相关测试。最终全量结果回写台账 01–05。

## 执行记录与验证

已完成 01–05。

- 公共 execute 的第二次角色解析继续传 projectTrusted；fake CLI 证明不受信任项目使用内置 reviewer，而非项目 prompt/model/tools。
- 角色发现与解析共用控制字符、行分隔符和 128 字上限；点号、空格和中文名保持可用。
- background 与 subagent 的状态目录检查所有者、类型和 POSIX 权限；当前用户已有的宽松目录迁移为 0700。清理路径只从合法 journal 文件名推导，journal 的 session ID 沿用现有 128 字形状，不强制 sub_ 前缀。
- 空调用工具列表和空角色覆盖都映射到 Pi 的 --no-tools；省略字段仍继承。
- background `security.test.ts` 3 项在 HEAD 快照全失败，修复后全通过；subagent `security.test.ts` 3 项和 `reap.test.ts` 7 项通过。
- `npm test --workspace subagent`：7 个文件、106/106；subagent typecheck 通过。background 全量验证在 U4 记录。

README 已同步角色名、空工具和私有 journal 目录。未强制所有内部 session ID 使用 sub_ 前缀，避免破坏合法自定义 ID。

## 三向审查追加修复

- 目录私有不足以防旧宽松目录中预置的条目：journal/pid/start 现在逐个 lstat，只读当前用户 regular file；符号链接或 foreign UID 使整份 journal 跳过，不退化为“缺少 marker”。
- recorded/current start 均存在时必须相等，命令行只在无法取得 start 时回退；subagent 回退匹配完整 --session/--session-id 参数，不再任意 substring。
- background 三类 symlink 与 stale-start 反例、subagent 两类 symlink 与 stale-start 反例均先失败后通过。最终 background reap 8/8，subagent reap+run 14/14，相关 typecheck 通过。

关闭时把信任、角色名、目录权限和 journal 推导路径的长期约束合入 Epic Spec，并在 Epic 关闭时毕业到 Project Spec。
