# 修正取消、上下文恢复与工具结果保留

## 目标与范围

完成台账 06、10、11、12、14、15：RPC abort 能关闭 ask_user；context-prune 不恢复 aborted reduce；Escape 暂停 goal 且不触发 compact；工具结果补丁保留 `structuredContent`；ask_user 顺序执行避免提前恢复 spinner。

修改 `ask-user`、`goal`、`auto-compact`、`context-prune`、`bash-timeout` 及对应测试和 README。不新增批次复核页，不改变 400k 阈值，不在 tool loop 中提前改写上下文。

## 方案

- AbortSignal 沿注册工具、执行助手传到 select 和 RPC input；工具声明 `executionMode: "sequential"`。
- context-prune 重建队列时只接受有成功配对结果的 ctx_reduce。
- goal 在真实 `agent_settled {aborted:true}` 路径暂停并持久化原因；auto-compact 对 aborted 直接返回。
- auto-compact README 写明连续 goal loop 中只在最终 idle 检查 400k，不承诺 continuation 中的硬上限。
- 两个工具结果补丁原样带回事件的 `structuredContent`。

## 质量承诺

- **可靠性**：取消不会产生延迟生效的 pruning、goal continuation 或压缩；对话框和 spinner 状态一致。通过宿主真实事件顺序验证。
- **兼容性**：文本内容增加提示时，codemode 等调用方仍取得原结构化数据。通过 ExtensionRunner 验证。

## 验证

新增 abort、structuredContent 和并发对话框检查先复现旧行为，再运行各 workspace 测试与 typecheck。context-prune 另跑恢复与裁剪边界测试，确保原文仍在 session 文件。
