# Domain Docs

This repository uses one root `GLOSSARY.md` and `docs/adr/` for domain documentation.

## Before exploring

Read `GLOSSARY.md`, then any ADRs in `docs/adr/` that touch the area you are working in. If either is absent, proceed silently. `/domain-modeling` creates them when terms or decisions are resolved.

## Use the glossary

Use the defined terms when naming domain concepts in issues, proposals, code, and explanations. If a needed concept is missing, check whether it belongs to the domain before proposing a glossary addition.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, identify the ADR and explain why the decision should be reconsidered.
